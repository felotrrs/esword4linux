# i18n — Spanish and English

## Mechanics

```
src/esword4linux/i18n/__init__.py   # tr(key, **kwargs), set_locale(), detect()
src/esword4linux/i18n/en.json       # English catalog (fallback)
src/esword4linux/i18n/es.json       # Spanish catalog
```

```python
from ..i18n import tr
tr("search.results_n", n=12, ms=34)   # → "12 results in 34 ms"
```

- `tr()` looks in the active locale, then **falls back to English**, then to
  Spanish, and finally returns the key. A missing translation never breaks the
  UI.
- `{}` placeholders are substituted with `str.format`. If a parameter is
  missing, the unformatted string is returned (no exception).
- `detect()` reads `LC_ALL`, `LC_MESSAGES` and `LANG`; unsupported or unset
  locales fall back to English.

## Rules

1. **Every visible string goes through `tr()`.** No literals in views.
2. **Keys are stable and identical in both JSON files.** When adding a key, add
   it to `en.json` **and** `es.json` in the same change.
3. **Naming**: `area.element` — `menu.file.scan`, `sidebar.ctx.open`,
   `bible.read_more`, `kind.bible`.
4. **Plurals are not concatenated by hand**: use a key with `{n}`.
5. **Biblical names do not live in JSON**: they live in
   `src/esword4linux/core/books.yaml` (`book_name(id, locale)`), because they
   are data, not UI strings.
6. **Category names do**: `kind.<kind>` in JSON; `KIND_LABELS` in
   `src/esword4linux/core/catalog.py` remains the fallback/CLI label.
7. **Library languages**: `lang.<code>` (`lang.es`, `lang.en`, `lang.grc`,
   `lang.hbo`, `lang.und`…) in both JSON files. The order lives in
   `src/esword4linux/core/catalog.py:LANGUAGE_ORDER` and the label is resolved
   by `src/esword4linux/ui/language.py`.
8. **Automatic workspace names** (`workspace.default_name`) are not stored as
   fixed text: `Workspace.name_auto` + `auto_letter` allow them to be
   recomputed on the fly when the language changes.

## Adding a language

1. Copy `en.json` to `<code>.json` and translate the values.
2. Add the code to `i18n._LOCALES` (tuple).
3. Add the code to `i18n.detect()` when appropriate.
4. The **Edit → Preferences → Language** combo is populated from
   `i18n.available()`; the main window does not need changes.

## Hot language switching

**Edit → Preferences → Language** stores `Settings.locale` and calls
`MainWindow._set_locale()`. That rebuilds the menus (`_build_menus()`) and runs
the explicit `retranslate()` of the sidebar, view-tabs and search; it does not
recreate widgets or lose tabs. Strings built only once must follow this
pattern: if a view does not expose `retranslate()`, switching language leaves
it in the previous locale.

## Documentation language

Documentation and code comments are **English-first**. The application UI is
bilingual Spanish/English through these JSON catalogs; Spanish is a supported
UI locale, not the documentation language.

.venv/bin/python - <<'PY'
import json
es = json.load(open("src/esword4linux/i18n/es.json"))

PY
